# 기기 간 일일 완료 동기화 계약 (전송 계층 선택 전)

목표는 같은 사용자의 한 기기에서 당일 대화를 완료하면 다른 기기도 같은 날 다시 요구하지 않는 것이다.
현재 문서는 네트워크 서버 구현 완료를 의미하지 않는다. 사용자는 우선 같은 Wi-Fi에서 동기화하는 방식을 선택했다.

## 공유하는 데이터

최소 v1은 프로토콜 버전과 완료된 하루 키(KST 04:00 기준 `YYYY-MM-DD`)의 집합만 교환한다. 하루 키 자체로 중복을 제거한다.
대화 본문, ChatGPT 로그인·쿠키, 비상 비밀번호, 수면 기록 원문은 전송하지 않는다.
ChatGPT 구독 계정을 별도 앱 로그인 서버처럼 사용하거나 모델 API를 호출하지 않는다.

## 상태 전이

- 완료 기록은 하루에 한 번 발생한 사실이며 중복 수신해도 결과가 같다.
- 상대 기기의 완료 기록을 받는 것만으로 현재 기기의 active day를 바꾸거나 다시 잠그지 않는다.
- 현재 활성 일자와 같은 기록이면 잠금만 조용히 해제한다. UI를 닫거나 대화를 새로 로드하지 않는다.
- 다음 날짜의 기록은 저장하되 그 날짜를 적용하는 명시적 로그인/잠금 해제 이벤트가 오기 전에는 현재 일자에 적용하지 않는다.
- 이미 완료한 현재 일자의 기록을 늦게 받아도 일일 완료 상태가 되돌아가지 않는다.
- 일부 턴을 기기끼리 더하는 기능은 현재 범위가 아니다. 한 기기에서 완료한 결과를 공유한다.
- 비상 해제 완료도 해당 사용자의 당일 완료로 공유한다. 잘못된 입력·비상 연속 횟수는 공유하지 않는다.
- 연결되지 않은 동안 다른 기기의 상태를 알 수 있다고 표시하지 않는다. 재연결 시 완료 기록을 교환하고 중복 적용하지 않는다.

## 페어링과 전송 계층의 책임

앱 사용자가 직접 연결한 기기만 완료 기록을 주고받는다. 네트워크 입력은 인증·형식 검증 후에만 상태 엔진으로 넘긴다.
개인 연결 키는 소스/설치 파일에 넣지 않는다. 설치마다 생성하고 로컬 설정에 보관한다.
원격 연결을 지원할 경우 호스팅 계정, 연결 유지 비용, 오프라인 동작을 별도로 확정한다.

## 같은 Wi-Fi 전송 구현 방향

PC의 기존 Windows 서비스가 선택적으로 로컬 네트워크 동기화 엔드포인트를 제공한다. UI를 트레이에서 종료해도 서비스가 기록을 전달할 수 있어야 한다.
휴대폰은 사용자가 PC에서 만든 연결 정보를 입력한 뒤에만 접속한다. 외부 중계 서버나 별도 계정은 추가하지 않는다.
PC가 만든 TLS 인증서의 SHA-256 지문과 무작위 연결 키를 휴대폰에 등록한다. 휴대폰은 그 인증서만 허용하고 요청마다 연결 키를 보낸다. 키는 TLS 안에서만 전송한다.
`POST /v1/sync`의 요청과 응답은 `{"version":1,"completedDays":["2026-09-25"]}` 형태이며 최대 32개 날짜, 8KiB를 허용한다.
PC 서비스에서 사용자가 연결을 켰을 때만 TLS 리스너가 열린다. Windows 네트워크 프로필 전체는 바꾸지 않고, 이 서비스 실행 파일·TCP 18431·동일 서브넷에 한정한 방화벽 규칙을 적용한다.
재시도/중복 기록은 일일 상태를 되돌리지 않는다. 휴대폰의 절전·프로세스 종료·네트워크 단절 중에는 즉시 동기화가 보장되지 않으며, 화면을 켜거나 앱에 돌아오면 다시 확인한다.
자동으로 공용 인터넷에 포트를 공개하거나 라우터 포트 포워딩을 설정하지 않는다.
실제 Wi-Fi 통신과 방화벽·앱 생명주기는 엔진 단위 테스트와 별도로 확인한다.

## 검증 기준

동일 일자의 완료 수신, 중복 수신, 아직 활성화되지 않은 일자의 수신, 앱 재시작, 하루 전환 직전/직후,
기존 완료 사유·로컬 진행 기록 유지, 오프라인 후 재연결을 양쪽 구현에서 검증한다.
전송 계층이 구현되기 전의 상태 엔진 테스트를 PC↔휴대폰 실제 동기화 성공으로 기록하지 않는다.
