# Android 확장 작업 기록

## 목표와 작업 분담

데스크톱 0.1.9의 동작을 유지하면서 Android 앱을 추가한다. 코드 위치는 기존 BREAKDOWN 루트 아래 `android/`이며, 데스크톱 경로는 이번 작업에서 옮기지 않는다.
공통 규칙은 대화 내용 무관 세 턴, 명시적인 세션/잠금 해제 시점의 일일 전환, 조용한 완료, 비상 해제이다.

- Android 잠금 모델 조사: docs/ANDROID_LOCK_MODEL.md
- ChatGPT 구독 웹과 로그인 가능성 조사: docs/ANDROID_CHATGPT_WEB.md
- 갤럭시 링 수면 접근 조사: docs/ANDROID_SLEEP_DATA.md
- Kotlin 상태 엔진: android/app/src/main/java/local/breakdown/mobile/core/
- 앱 연결·검증·기기 간 동기화·배포: 메인 작업에서 통합

워커 모델은 사용자가 선택한 `chatgpt-web/gpt-5.6-sol`, reasoning High이다.

## 확인한 개발 환경

Ubuntu WSL 2: Java 17, Gradle 8.10.2 캐시, AGP 8.8.2, Kotlin 2.1.10을 사용한다.
AGP 8.8의 지원 상한은 API 35이므로 기존 SDK에 Android 35 플랫폼을 추가한다.
참고: https://developer.android.com/build/releases/agp-8-8-0-release-notes

테스트 기기는 사용자 소유 Galaxy S26이다. USB 연결 테스트가 가능하다고 확인했으나 아직 실제 연결·Android 버전·권한 설정·로그인 성공은 확인하지 않았다.
일반 설치 상태에서 시작한다. 기기 초기화, Device Owner 등록, 권한 자동 허용은 하지 않는다.

## 완료로 간주하지 않는 것

초기 앱 셸이 빌드되거나 단위 테스트가 통과해도 웹 로그인, 실제 턴 감지, 다른 앱 사용 제한, 양쪽 기기의 하루 완료 동기화가 구현·검증된 것은 아니다.
실제 계정·기기 확인 전에는 정식 배포나 잠금 활성화를 성공했다고 기록하지 않는다.
갤럭시 링 수면 판정 기준은 사용자가 나중에 정할 사항으로, 임의의 수면 시간 임계값을 확정하지 않는다.

## 초기 빌드 확인

WSL에서 기존 Gradle 캐시를 사용한 `--offline wrapper --gradle-version 8.10.2 --distribution-type bin :app:assembleDebug`가 성공했다(34 tasks).
현재 APK는 안내 화면만 있는 앱 셸이며 로그인이나 잠금은 아직 구현하지 않았다. 기기에 설치하거나 공개 배포하지 않았다.
Gradle wrapper를 소스 폴더에 수집했고 테스트 APK는 Git에서 제외되는 `artifacts/android/`에 보관한다.

## 기능 통합 및 실제 기기 연결

- 순수 Kotlin 상태 엔진, SharedPreferences 상태 저장, PBKDF2 비상 비밀번호, 대화 선택과 WebView 관찰 연결, 사용자 활성화 접근성 오버레이를 통합했다.
- 엔진·URL 단위 테스트 7개와 `assembleDebug`를 WSL에서 통과했다. 첫 테스트의 오전 4시 직전/직후 시각 표본 오류를 수정했다.
- 모바일 JavaScript 관찰기는 데스크톱의 probe/tracker에서 생성한다. 일일 scope와 대화 revision을 기준으로 오래된 결과를 제외한다.
- WebView·오버레이 워커는 구현 도중 ChatGPT 요청 제한으로 중단되어, 저장된 코드와 조사 결과를 메인 작업에서 이어받았다.
- Galaxy S26(SM-S942N), Android 16/API 36의 USB 디버깅 연결을 확인했다. Windows ADB가 WSL 서버로 연결되던 충돌은 별도 Windows 서버 포트 5038을 사용해 분리했다.
- 정식 앱과 데이터가 섞이지 않는 `local.breakdown.mobile.dev` 개발용 APK를 S26에 설치하고 실행했다. 접근성 권한과 일일 잠금은 자동으로 활성화하지 않았다.
- 실제 ChatGPT 로그인 성공 여부는 사용자의 확인을 기다리는 중이다. 잠금 실기기 검증, 기기 간 동기화, 수면 adapter 및 배포는 아직 완료하지 않았다.

## 동기화 상태 규칙

Android와 Windows 엔진에 인증된 상대 기기의 완료 기록을 적용하는 내부 API를 추가했다.
같은 날 중복 수신, 앱/서비스 재시작, 다음날 기록의 선 수신과 명시적 세션 이벤트 적용을 검증했다.
Android 테스트 10개와 Windows 검사 68개를 통과했다. 현재 네트워크 페어링·전송 계층은 없으므로 실제 기기 간 동기화가 된다는 의미는 아니다.
사용자는 우선 같은 Wi-Fi에서 동기화하는 방식을 선택했다. PC의 기존 백그라운드 서비스와 휴대폰을 직접 연결하는 전송 계층을 다음 단계로 구현한다.

## 로컬 TLS 전송 구현

PC 서비스의 선택적 TLS 엔드포인트와 연결 키/인증서 지문, Android 고정 지문 HTTPS 클라이언트, 완료 상태 스케줄러, 양쪽 연결 설정 화면을 구현했다.
PC는 사용자가 연결을 켤 때만 리스너 및 해당 프로그램·TCP 18431·동일 서브넷 한정 방화벽 규칙을 만든다. OS 네트워크 프로필 전체를 바꾸지는 않는다.
격리된 PC loopback 테스트에서 TLS 지문·연결 키 검증, 완료 날짜 송수신, 중복 처리, 연결 끄기를 통과했다.
Android 테스트 18개와 APK 빌드가 통과했고, 숨겨진 PC 설정 화면의 연결 정보 생성·복사·끄기도 통과했다.
S26에 설치된 로그인 확인용 빌드는 아직 이 네트워크 연결 UI 추가 전 버전이다. 사용자의 로그인 확인을 기다리는 동안 앱을 교체하지 않았으며, 실제 Wi-Fi 통신은 별도 검증이 남아 있다.

## S26↔PC 실제 Wi-Fi 전송 검증

Android의 실제 `PeerClient`를 그대로 사용하는 별도 instrumentation 모듈 `sync-probe`를 만들었다.
Galaxy S26과 PC가 동일한 Wi-Fi/LAN 서브넷에 있는 상태에서 TLS 연결, 완료 기록 업로드·조회, 중복 기록, 잘못된 키·지문 거부를 검증했다.
결과는 `PASS sync-probe`, `success=true`이며 PC의 격리된 테스트 DB가 동기화 사유로 해제되는 것도 확인했다.
첫 시도는 Android의 간략 출력 형식 때문에 테스트 실행기의 성공 판독에 실패했고, `am instrument -w -r`로 결과를 읽도록 수정한 뒤 통과했다.
테스트는 S26 주소 하나에만 허용한 임시 방화벽 규칙을 사용했고, 완료 후 규칙·테스트 앱·가상 DB를 제거했다. 실제 사용자의 로그인·대화·진행 DB는 사용하지 않았다.
PC 연결 QR 생성과 표시도 숨겨진 UI 테스트로 확인했다. 데스크톱 개발 소스 버전은 동기화 추가를 구분해 0.2.0으로 올렸으며, 아직 현재 설치된 0.1.9를 교체하지 않았다.
이 검증은 실제 ChatGPT 로그인·대화 감지·접근성 잠금의 실기기 통과를 대신하지 않는다.

## 배포 후보와 관찰 결과 재전달

데스크톱 0.2.0 전체 빌드에서 Windows 검사 68개·TypeScript 테스트 23개·Named Pipe·TLS·DOM·설정 UI·QR·패키지 검사를 통과했다.
기존 설치 위치에 0.2.0을 적용하고 기존 대화 설정 및 당일 3/3 기록을 확인했다. 동기화 기능은 기본 꺼진 상태이다.
Android는 저장소 밖에 보관한 키로 서명한 `0.1.0-alpha1` APK 후보를 생성했다. 정식 사용자 앱 ID와 개발용 앱 ID를 구분하며, 후보는 아직 설치하거나 게시하지 않았다.
화면 전환으로 native callback이 폐기돼도 이벤트가 사라지지 않도록 모바일 관찰기에 수신 확인과 재전달을 추가했다. 합성 ChatGPT DOM에서 재전달·중복 제거·scope 전환·본문 미반출을 검증했다.
실제 계정 로그인 성공 여부와 접근성 잠금 검증은 계속 사용자 확인을 기다린다. 이 확인 없이 정식 모바일 릴리스 완료로 기록하지 않는다.

## 실제 로그인 확인

사용자가 S26 개발용 앱에서 로그인에 성공하고 대화 화면이 보인다고 확인했다.
이후 같은 앱 ID·개발용 서명으로 최신 빌드를 `install -r` 업데이트하고 실행했다. 데이터 초기화나 제거는 하지 않았다.
현재 선택한 기존 대화에서 새 입력·응답 한 쌍이 테스트 1/1로 감지되는지 사용자 확인을 진행 중이다. 접근성 잠금은 아직 자동으로 켜지 않았다.

사용자가 실제 대화에서 테스트 표시가 1/1로 바뀌었다고 확인했다. 다음으로 사용자가 직접 접근성 권한을 켜고, 다른 앱 차단 및 새 대화 세 쌍 후 해제를 확인하는 단계이다. 이 단계에서는 PC 연결을 켜지 않아 모바일 자체의 3턴 규칙을 독립적으로 확인한다.
추가로 비밀번호 계산 또는 PC 연결 도중 취소한 경우 늦게 도착한 결과로 설정이 저장되지 않도록 보완했고, 서명 APK 후보를 갱신했다. 현재 진행 중인 휴대폰 테스트를 방해하지 않도록 이 후속 수정으로 앱을 재시작하지는 않았다.

## 릴리스 준비 상태

`breakdown-v0.2.0`(Windows)와 `breakdown-android-v0.1.0-alpha1`(Android)의 GitHub 릴리스 초안을 만들고 설치 파일과 체크섬을 업로드했다.
두 릴리스 모두 draft이며, Android는 prerelease로도 표시했다. 아직 공개 배포하지 않았다.
Android 접근성 차단·실제 세 턴 해제 결과를 기다리며, 결과 확인과 최종 자료 갱신 후 공개 단계로 진행한다.

## 사용자 기능 확인과 PC 연결 승인 대기

사용자가 모바일의 차단·세 턴 해제를 포함해 모두 정상으로 보인다고 알려주었고, PC 연결은 아직 하지 않았다고 명시했다.
설치된 PC 앱의 실제 동기화 활성화 및 S26용 QR 생성은 자동 승인 검토에서 명시적 승인 부족으로 거절됐다.
이 작업은 동일 서브넷의 앱 TCP 18431 방화벽 허용과 연결 자격정보 생성을 포함하므로, 사용자에게 구체적인 승인을 요청했다. 거절된 작업을 다른 경로로 실행하지 않았다.

## 최종 실기기 확인

사용자가 PC 연결 활성화·동일 서브넷 포트 허용·S26 QR 생성을 명시적으로 승인했고, 실제 PC 서비스를 활성화했다.
첫 앱 연결은 실패했으나 재시도 후 사용자가 동기화 성공을 확인했다. PC 내부 TLS 요청도 HTTP 200으로 응답했다. 첫 실패의 원인은 확정하지 않았다.
사용자 승인으로 S26을 재부팅했고, 전후의 민감값 제외 상태가 동일함을 확인했다(당일 3/3, 대화·비밀번호 설정 여부, PC 연결 설정, 공유 완료 기록).
접근성 권한이 유지되고 서비스가 다시 실행된 것도 확인했다. PC 동기화만 35초 끊었을 때도 휴대폰 상태는 동일했고 정상 복구했다.
배터리 진단의 앱 구간을 확인했으나 USB 충전 중의 짧은 기록으로 장기 소모량을 판단하지는 않았다. 전체 휴대폰 인터넷 단절·장기 절전·타 제조사 검증은 남은 한계로 기록한다.

## 공개 및 마무리

Windows 0.2.0과 Android 0.1.0-alpha1을 공용 GitHub Releases에 공개했다(Android는 prerelease).
소스는 main에 반영했고 WSL 작업 사본도 동일 커밋으로 정리했다. 메인 README에서 두 플랫폼의 릴리스 링크를 실제로 눌러 정상 페이지가 열리는 것을 확인했다.
업로드된 설치 파일·APK의 SHA-256은 로컬 후보와 일치한다. 서명 키·비밀번호·개인 대화 설정·QR 연결 정보는 Git에 포함하지 않았다.
S26의 기존 개발용 앱은 동일 서명으로 최종 수정본에 업데이트했으며 당일 3/3·설정·PC 연결 상태가 그대로임을 비교했다. 배포용 APK는 별도 앱 ID이므로 사용자가 전환할 때는 개발용 접근성 제한부터 끄고 새로 설정한다.
장기 배터리·모든 제조사 절전 조건·전체 인터넷 단절의 보장은 하지 않으며, 알파 릴리스 설명에도 이 범위를 명시했다.
