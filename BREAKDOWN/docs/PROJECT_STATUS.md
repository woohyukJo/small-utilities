# 프로젝트 결정사항과 현재 상태

기준일: 2026-10-11. 설치된 개발 버전은 Windows 0.2.1, S26 Android 0.1.2-alpha3-dev다. Firefox 확장 0.2.0은 Mozilla 서명과 S26 영구 설치를 완료했다. 공개 릴리스는 Windows 0.2.0과 Android 0.1.0-alpha1을 유지한다.
이 문서는 대화 기록 원문이 아니라 확정한 요구사항과 확인 범위를 정리한다.

S26 개발용 앱은 Firefox 패스키 로그인/대화 연결을 사용한다. 4시 예약과 놓친 날짜 보정, 실제 앱 연결은 구현했으며 잠금은 꺼져 있다. 2026-10-11에 서명된 확장을 영구 설치하고 Firefox 재시작 후 설치와 앱 연결 유지를 확인했다. 사용자가 실제 1턴 확인 뒤 나머지 실대화 검사를 생략하도록 요청했다. 자세한 이력은 MOBILE_WORKLOG.md와 firefox-extension/README.md에 남긴다.

## 다음 작업 시작점

- Firefox 확장 0.2.0의 서명·영구 설치는 완료됐다. 다음 버전 서명은 `scripts/sign-firefox.ps1`, 승인 대기 요청의 조회/다운로드는 `scripts/fetch-firefox-signature.cjs`를 사용한다. 키는 로컬 `.dev/amo-signing.json`에 두며 Git에 넣지 않는다.
- 실제 모바일 잠금은 꺼져 있다. 사용자가 명시적으로 시작하기 전에는 활성화하지 않는다. Firefox의 패스키 로그인과 실제 1턴 전달은 확인했고, 남은 실대화 2턴 검사는 사용자 요청으로 생략했으므로 다시 필수 단계로 요구하지 않는다.
- Firefox 재시작 후 연결 유지는 확인했다. 활성 잠금 상태의 실제 3턴 해제, 자연 경과한 4시, 장기 절전은 검증한 것으로 기록하지 않는다.
- 빌드에 필요한 `.tools`, `node_modules`, SDK는 정리 대상으로 보지 않는다. 캐시/생성물도 재빌드 비용을 고려해 필요한 것만 정리한다.

## 확정한 동작

- 하루 한 번 지정한 ChatGPT 대화에서 새 사용자 입력과 정상 완료된 답변 세 쌍을 진행하면 사용 제한을 해제한다.
- 내용이나 할 일의 품질은 판정하지 않는다. 마침표 세 번으로 해제하는 것도 의도된 사용 방식이다.
- 모델 API 없이 기존 ChatGPT 구독의 웹 대화를 사용한다.
- 임시 하루 기준은 KST 04:00이다. 사용 중 갑자기 잠그지 않고 다음 Windows 로그인 또는 화면 잠금 해제에서 새 하루를 적용한다.
- 선택한 기존 대화를 계속 열며 과거 기록을 오늘의 턴으로 세지 않는다. 세션은 사용자가 바꿀 수 있는 런타임 설정이다.
- 세 턴 후에는 조용히 잠금만 해제한다. 창 크기·포커스·입력·스크롤을 유지하고 ESC로 이전 창 모드에 돌아간다.
- 해제 후 트레이 종료는 UI와 트레이를 종료한다. 같은 날 감시 프로세스가 다시 띄우지 않고, 다음 날 로그인의 자동 실행을 위해 서비스는 남는다.
- 일반적인 종료와 창 전환을 통한 우회를 막는 자기통제 도구이다. Windows 계정을 새로 만들거나 관리자 권한을 제거하지 않는다.
- 비상 비밀번호를 열 번 연속 정확하게 입력하면 당일 해제한다. 오입력·취소·재시작은 연속 횟수를 초기화한다.
- MIUUYY는 구조만 참고한다. 프로그램·프로필·쿠키·설정·포트를 공유하거나 의존하지 않는다.

## 0.1.8까지 구현 및 확인한 범위

- Electron 웹 UI, DOM 기반 턴 감지, .NET Windows 서비스, SQLite 상태 저장, 설치/제거 도구를 구현했다.
- 사용자 환경에서 로그인과 세 턴 해제가 동작했다.
- 정상 종료 RPC 후 UI 프로세스가 사라지고 다시 실행되지 않는 것을 확인했다. 실제 트레이 클릭 자동화와는 구분한다.
- 화면 깜빡임은 가림창의 반복적인 최상위 전환을 원인으로 가정하여 수정했다. 원래 증상을 재현하거나 원인을 확정하지는 못했다.
- 이전 검증 결과는 TypeScript 23개 테스트와 .NET 48개 검사, Named Pipe 및 숨겨진 Chromium 검사였다.

## 0.1.9 검증

- TypeScript 23개 테스트, .NET 63개 검사 및 실제 Named Pipe 통신 검증을 통과했다.
- A→B→A 대화 변경 뒤 이전 revision의 제출·완료·준비 완료 요청이 거부되는 것을 검증했다.
- 실제 설정 UI를 숨겨진 Chromium에서 열어 URL 초안 보존, 오류 표시, 초기 설정 조건, 잠금 중 대화 재설정, 조용한 해제를 확인했다.
- 전체 Electron main-process의 DOM/RPC 지연 순서를 자동으로 재현하지는 않았다. 코드의 epoch 검사와 서비스 revision 검사를 검토했으며 실제 시스템 확인 범위는 VALIDATION.md에 남긴다.

## 이번 작업: 개인 설정 없는 배포 빌드

- 소스에 들어간 개인 대화 ID를 제거하고 기존 DB에서 선택한 대화를 읽는다.
- 대화 URL 붙여넣기와 현재 열린 대화 선택을 제공한다.
- 새 설치에는 대화 선택·비상 비밀번호·테스트 대화 설정이 필요하다.
- 기존 설치는 DB에 기록된 대화 설정을 이전하고 로그인·비밀번호·일일 진행 상태를 유지한다.
- 대화 변경 시 진행 중 응답은 분리하되 이미 완료한 당일 턴과 잠금 해제 상태는 유지한다.
- 공개 저장소라는 이유로 별도의 계정 서버나 과도한 보안 기능을 추가하지 않는다.

## 모바일 및 동기화 검증

- Android 네이티브 Kotlin 앱을 WSL에서 빌드하고, 데스크톱과 같은 ChatGPT DOM 관찰 로직을 사용한다.
- S26/Android 16에서 로그인·1턴 감지·다른 앱 차단·3턴 해제를 사용자와 확인했다.
- 같은 로컬 네트워크에서 TLS 지문/연결 키 기반 완료 상태 교환을 구현했고, 실제 앱 연결과 별도 기기 테스트를 통과했다.
- 실제 휴대폰 재부팅 뒤 당일 완료·설정·접근성 서비스가 유지됐고, 동기화 연결 중단 중에도 완료 상태를 유지했다.
- Windows 검사 68개, TypeScript 테스트 23개, Android 테스트 18개, 통신·DOM·설정 UI·QR·서명 빌드 검사를 통과했다.
- 첫 실제 PC 연결의 일시적 실패 원인은 확정하지 못했다. 장기 배터리/대기 및 모든 제조사 동작까지 검증한 것은 아니다.

## 후속 작업

- 같은 Wi-Fi/LAN 밖에서의 동기화는 아직 지원하지 않는다.
- 갤럭시 링→Samsung Health→Health Connect 경로를 조사했다. 수면 기반 하루 시작 판정과 실제 건강 데이터 연결은 아직 구현하지 않았다.
- 지금은 Windows 서비스 코드를 모바일로 그대로 이식하거나 공통 프레임워크로 다시 작성하지 않는다.
